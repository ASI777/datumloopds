# ECX FLAT 22 L bracket — source ledger

The first part is a motor carrier for one Z-spindle head in a precision
placement machine. The source record is `requirements.json`. It is deliberately
source-only: unresolved machine and bracket requirements remain unknown.
The user has delegated application selection and optimization; subsequent
study-specific selections must be recorded separately from manufacturer data.

- Document: [official catalog page 259](https://www.maxongroup.com/medias/sys_master/root/9399287709726/Cataloge-Page-EN-259.pdf).
- Revision: February 2025, provisional data, subject to change.
- PDF page 1, printed page 259. SHA256:
  `9aa3139520c7f4c6cdd5c74c1dafe24df351556142f77a1e26500e9c2b405d17`.
- The original front/end and side views were rendered and visually inspected;
  values were transcribed from callouts, not measured from pixels.
- This is a configurable family reference; a configured motor must be checked
  against this interface before manufacturing. The integrated-electronics motor
  is a different configuration and is not silently substituted.

The bracket does not reproduce the motor's shaft, connectors or internal
features. Its future locating bore is a precision interface, with a selected
fit/tolerance to be recorded independently. A thread depth is not an approved
screw engagement or screw length. Manufacturer GD&T is not transferred to a
new bracket without a separate datum/tolerance decision.

## Executed slice

Native requirements ingestion, unit conversion, source/derivation validation,
fixed-interface protection, bounded edits, quantitative criterion evaluation,
and `.dld` persistence are implemented. The dedicated test exercises source
unknowns, rejected interface changes, atomic bound rejection, failed and passing
criterion values, and schema-eight migration. No bracket geometry, machine-part
mesh, structural result or optimized design is claimed by this source slice.

## Selected reference application and generated candidate

`design-study.json` applies the user's delegated application choices to the
source-only record. The component carries a transverse motor driving one
Z-spindle through a belt/pulley. Local Z is the motor shaft/plate normal;
local XY is the plate. The selected normal acceleration load is an envelope
for gantry motion in the normal direction, not a measured machine trajectory.
The nozzle's precision rail/bearings and belt compliance are not modeled.

The study defines a new gantry interface rather than claiming to recover an
existing machine's mounting pattern. It fixes two M4 clearance holes and two
precision 3 mm locating bores for a round/diamond-pin mating arrangement.
Motor and gantry holes remain fixed while thickness can vary 1.5–5.5 mm.
All these selections have their own engineering source record. A configured
motor drawing and actual mating hardware still require assembly review.

The generated native part now has a rectangular-profile extrusion and eight
semantic through-hole features: the motor pilot bore, three M2 clearance
bores, two M4 clearance bores and two precision dowel bores. Every numeric
feature parameter retains source parameter IDs, the generation relationship,
and a source-value snapshot. Attaching changed requirements to stale geometry
is rejected. `.dld` stores the editable graph, exact solid, persistent interface
face UUIDs, requirements and the existing NIST-compiled 6061-T6 material model.
The graph is regenerated by the native recipe; the relationship text is
provenance, not an unverified arbitrary expression interpreter.

```sh
cmake --build build --target datumloop-part-design
build/datumloop-part-design \
  --requirements examples/parts/maxon-ecx-flat-22-l/design-study.json \
  --output build/part-design/candidate-1
# Explicit parameter study; this is not automatic FEA-driven redesign:
build/datumloop-part-design \
  --requirements examples/parts/maxon-ecx-flat-22-l/design-study.json \
  --thickness 2.5 --output build/part-design/candidate-2
build/apps/datumloop-desktop/DatumLoopDS \
  --project reports/machine-part/initial/carrier.dld
```

Candidate directories are not overwritten. The native generator emits `.dld`,
exact BRep, source requirements, geometry and manufacturing reports, and a
disposable display mesh. The preserved initial candidate and review image are
in [`reports/machine-part/initial`](../../../reports/machine-part/initial).

Material selection is 6061-T6 with the same sourced density, Young's modulus,
Poisson ratio and reported uncertainties as the existing verified CAE slice.
No yield value or property temperature range is invented. The 100 MPa study
stress cap is an explicitly selected screening criterion, not a sourced safety
factor. The pilot/bore limits permit up to 45 µm radial clearance; the 5 µm
criterion concerns elastic deflection, not assembly locating accuracy.

Geometric manufacturing screening covers retained walls, hole depth ratio,
axial tool reach, motor screw engagement/depth, stated precision bore limits,
normal tool access, absence of undercuts in this recipe and a two-side geometric
setup plan. Workholding capacity, toolholder interference and achieved
accuracy remain unqualified. Unsupported geometry returns unknown. No FEA or
automatic engineering redesign has been executed for this carrier yet.
